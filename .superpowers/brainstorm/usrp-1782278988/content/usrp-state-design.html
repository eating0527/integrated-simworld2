設計一：任務與雙服務狀態

一個 mission 包含 UAV GPS 與 USRP Noise 兩個獨立子任務；同時啟動、分開監控、以相同 mission_id 配對。

本機任務協調器
mission_id · selected_mode · created_at · overall_state
UAV GPS
connection: ready / offline
state: idle / running / stopped / failed
file: gps.csv
USRP Noise
connection: ready / offline
state: idle / running / stopped / failed
file: noise.csv

開始規則

  1. 確認 AP3／USB GPS 可用。
  2. 透過短 SSH 連線確認 RasPi 可達、目標 service 可操作，而且沒有既有任務。
  3. 建立唯一 mission_id，先持久化本機任務狀態。
  4. 以同一 mission_id 啟動本機 GPS worker 與遠端 test／usrp service。
  5. 若啟動階段其中一路仍失敗，另一條已啟動的服務繼續執行，整體標記 partial_failed。

連線與執行狀態分離

connected + running
offline + presumed_running
connected + stopped
connected + failed

SSH 中斷時不能把 service 標記 stopped；只能顯示離線且最後已知為 running。重連後重新查 systemd 與 RasPi mission.json 校正。
