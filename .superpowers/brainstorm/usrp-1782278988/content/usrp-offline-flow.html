USRP 離線持續與重連恢復架構

SSH 只負責下達命令；真正的任務生命週期由 Raspberry Pi 上的 systemd 管理。

目前流程：SSH session 導向
控制
前端 → 後端 → 長駐 SSH client → systemctl
資料
watcher → uploader → 多個 CSV API → incoming

問題

  • 連線狀態與任務狀態混在一起
  • 重連後缺少可靠的任務識別
  • 停止 service 不等於 CSV 已封存並回傳
建議流程：RasPi 任務導向
1. 啟動
前端選模式 → POST start → systemd start
2. 離線執行
service 持續採樣 → 寫入 mission 暫存目錄
3. 重連恢復
GET status → 讀取 service + mission.json → 還原前端狀態
4. 停止與回傳
POST stop → SIGTERM → flush CSV → 封存 → HTTP 上傳

最少必要元件

1

兩個 systemd service

測試與 USRP 各一個，共用同一個任務腳本。

2

一份 mission.json

保存 mission id、模式、PID、開始時間、CSV 路徑與上傳狀態。

3

三個控制 API

status、start、stop；每次請求使用短 SSH 連線。

4

一個 CSV 回傳流程

停止時先安全關閉、再封存並上傳；失敗則留在 RasPi 待重試。
