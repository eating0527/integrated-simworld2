> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each phase task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 分階段移除 `sim/gps` 對 UNet 的依賴，並只讓 `gps_n` 使用新的 3-channel UNet。

**Architecture:** 保留既有 `/api/iss-unet/*` API 與前端契約。`sim/gps` 改成不載入 UNet 的 Sionna/GPS 結果路徑；`gps_n` 使用 `[sparse_rss, sampling_mask, building_height_norm]` 進入新模型。模型權重放在本機 ignored artifact 目錄，不納入 git。

**Tech Stack:** Python, FastAPI backend, NumPy, PyTorch, Matplotlib, pytest/unittest。

## Phase 依賴順序

```text
Phase 1 -> Phase 2 -> Phase 3 -> Phase 4 -> Phase 5 -> Phase 6
```

這個順序的理由：

- Phase 1 先建立 failing tests，避免後續改動只靠人工判斷。
- Phase 2 先把 `sim/gps` 從舊 UNet 拆開，降低新模型導入時的影響範圍。
- Phase 3 只處理新模型程式碼與權重安全，避免和 inference 行為混在一起。
- Phase 4 專心處理 3-channel adapter 與 normalization，這是最容易出錯的資料契約。
- Phase 5 才把 `gps_n` 正式接上新模型。
- Phase 6 做整體驗證與提交前清理。

## 跨 Phase 不變條件

- API path 不改：`/api/iss-unet/status`、`/api/iss-unet/reconstruct`、`/api/iss-unet/reconstruct/upload` 維持既有契約。
- 前端不需要知道模型從 5-channel 換成 3-channel。
- `sim` 與 `gps` 不應載入任何 UNet checkpoint。
- `gps_n` 不應呼叫舊的 `_load_model`。
- 新模型權重只允許存在於本機 ignored path。

## 目標模式行為

| Mode | 目標行為 | 使用 UNet | 輸出 map 來源 |
|---|---|---:|---|
| `sim` | 使用 Sionna/data-backed ISS map，不載入模型 | 否 | `arrays["iss"]` |
| `gps` | 使用 GPS route 與 Sionna-backed map，不載入模型 | 否 | 預設採 dense `arrays["iss"]`，保留 GPS metrics |
| `gps_n` | 使用 GPS + noise sparse samples 進新模型 | 是，新 3-channel UNet | 新模型預測，denormalize 至 `[-90, -15] dBm` |

## Channel 對照

| 現有 5-channel | 定義 | 新 `gps_n` 3-channel |
|---|---|---|
| `building_norm` | 建物高度圖，正規化到 `[0, 1]` | `building_height_norm` |
| `sparse_iss` | 採樣點上的稀疏訊號值 | `sparse_rss` |
| `sparse_mask` | 採樣遮罩，`1` 表示該 pixel 有量測 | `sampling_mask` |
| `outdoor_mask` | 戶外有效區域遮罩 | 從模型輸入移除，仍可用於後處理、metrics、CFAR |
| `dss_norm` | Sionna DSS/pathloss 先驗 | 從模型輸入移除 |

## 實作前建議

先從 Phase 1 開始，不要直接跳到 Phase 5。這次改動的主要風險不在模型 class 本身，而在 mode routing 與資料 normalization；先讓測試描述目標行為，後續每階段會比較容易確認沒有誤傷 `sim/gps`。
