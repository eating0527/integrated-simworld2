# 前端操作工作區改版設計

## 目標

在不改動後端、API、WebSocket、GPS、相機、採樣與無線模擬工作流的前提下，重新整理桌面版操作介面。改版後應減少面板遮擋、保留最大的 3D 場景視野，並讓場景切換、控制、遙測與監看資訊具有清楚且一致的層級。

## 範圍

本次改動包含：

- 頂部場景選擇器。
- 裝置設定、UAV 控制、無人機遙測、採樣控制、連線狀態、無人機畫面與無線模擬面板的外層版面與互動。
- 照片紀錄的停靠與預設收合，避免遮擋主要操作區。
- 面板收合、垂直縮放、側欄顯示切換與窄螢幕抽屜行為。
- 共用色彩、間距、字級、狀態與動態規則。

不在本次範圍：

- 無線模擬面板內部八個子面板的內容、結構或業務互動。
- 任何 API 路徑、請求內容、WebSocket 訊息、GPS 計算、相機串流、採樣流程或後端服務。
- 面板自由排序、自由浮動、分離視窗與跨工作階段版面保存。
- 手機端既有拍照與定位流程。

## 選定方案

採用左右雙側工作區。左側集中設定與控制，右側集中狀態與監看；中央只保留 3D 場景。這比底部控制台更適合長表單與影像，也比自由浮動面板更不容易遮擋、遺失或在不同解析度失效。

## 視覺方向

介面採精密任務控制台風格：深石墨半透明表面、低對比線框、青綠色主要操作提示，橙色與紅色僅用於警告和停止狀態。避免裝飾性漸層與高成本特效，讓 3D 場景保持視覺主體。

- 共用 CSS 變數管理背景、邊框、文字、狀態色、陰影、圓角與間距。
- 使用本機字型堆疊；遙測數值使用等寬字型，不載入網路字型。
- 標題列、狀態膠囊、欄位、按鈕與輸入元件使用一致尺寸與焦點樣式。
- 動畫只用 CSS，時間短且可預測；`prefers-reduced-motion` 下停用非必要動態。

## 版面架構

`App` 的資料與功能元件保持原狀，只在外層加入工作區殼層：

1. 頂部 `SceneSwitcher` 成為固定任務列，置中顯示目前場景、預設場景與生成場景選單。
2. 左側工作欄由上至下放置 `DevicePanel`、`UAVControlPanel`、`USRPTelemetry`。
3. 右側工作欄由上至下放置 `AircraftTelemetry`、`GPSStatus`、`ControllerScreenPanel`、`SimulationPanel`。
4. `PhotoViewer` 保留於右側次要區域並預設收合。
5. `MainScene` 維持全畫面背景；工作欄與頂部列覆蓋其上，但欄內自行捲動，不讓頁面本身捲動。
6. `CameraUpload` 的手機端呈現與邏輯不變。

桌面寬度下，左右欄寬度使用 `clamp()` 保持合理範圍。低於約 1100px 時，工作欄改為覆蓋式抽屜，一次只顯示一側。既有手機判斷仍決定哪些桌面面板不渲染。

## 元件設計

### 工作區殼層

在 `App` 中加入語意化工作區容器、左右欄及欄開關狀態。殼層只負責排列與顯示，不接觸子元件的業務 props。桌面欄內使用正常文件流，取代各面板的 `fixed`、`absolute` 與獨立 z-index 座標。

### 共用面板 `MinPanel`

沿用現有 `MinPanel`，移除自由拖曳作為預設操作，強化以下共同行為：

- 標題按鈕切換收合／展開，並提供 `aria-expanded`。
- 收合時保留子元件掛載狀態，避免中斷串流、輪詢或表單狀態。
- 隱藏內容不可被滑鼠或鍵盤操作。
- 展開內容使用原生 CSS `resize: vertical`，並設定最小與最大高度。
- 標題列可放置既有狀態膠囊，不改變其來源資料。
- 面板外框、標題、內容捲動與縮放握把採共用樣式。

不新增拖放套件，也不保存自訂版面。固定資訊層級能以更少狀態達成穩定操作。

### 場景選擇器

保留 `selectedScene`、`onSelectPreset`、`onSelectGenerated` 與生成場景狀態的既有資料流，只將大量行內樣式移至 SCSS：

- 顯示目前任務／場景識別。
- 預設場景按鈕使用一致分段控制樣式。
- 生成場景維持可鍵盤操作的下拉清單、外部點擊關閉與 Escape 關閉。
- 窄寬度允許水平捲動或壓縮次要標籤，不換成新的選擇流程。

### 無線模擬面板

只調整 `SimulationPanel` 最外層 `MinPanel`、標題列、最大高度及內容捲動容器。內部八個子面板、按鈕、表單、請求與回呼不改名、不移動、不重構。

## 互動規則

- 頂部列永遠高於工作欄；工作欄內容不會蓋住場景列。
- 左右欄各有顯示切換按鈕，隱藏後中央場景立即取得更多空間。
- 窄螢幕抽屜互斥；開啟左側會關閉右側，反之亦然。
- Escape 關閉目前開啟的窄螢幕抽屜或生成場景選單。
- 面板縮放僅改變自身高度，寬度由工作欄控制；欄內其餘面板依正常流重新排列。
- 每個互動控制都有可見焦點、可理解標籤與至少 44px 的主要觸控目標。

## 資料流與功能隔離

`App` 仍持有現有狀態與回呼，並把相同 props 傳給相同功能元件。工作區只新增純 UI 狀態，例如左欄是否開啟、右欄是否開啟及面板是否收合。以下資料流不得改變：

- 場景選擇到 `MainScene` 與 `SimulationPanel` 的場景識別。
- UAV 手動、自動、動畫與 GPS 回放控制。
- GPS、裝置、遙測與連線狀態。
- 採樣啟停、模式、綁定、輪詢與 mission 狀態。
- 控制器影像、照片與相機串流。
- CFAR、熱圖、路徑與無線模擬結果。

## 錯誤處理

本次不改寫現有錯誤處理。各功能面板仍顯示原本的請求、相機、串流或模擬錯誤。版面層只需確保錯誤內容可在面板內捲動，不會撐破工作欄或遮住其他控制。

## 效能

- 不新增執行期依賴。
- 使用 CSS Grid、正常文件流、CSS 變數與原生 resize。
- 不為游標移動建立全域拖曳監聽器。
- 收合面板保持掛載，避免不必要的串流與輪詢重建。
- 動畫以 `transform`、`opacity` 與短時間過渡為主。
- 只在工作區殼層保存少量顯示狀態，避免建立新的全域 store。

## 測試與驗證

自動測試應覆蓋：

- `MinPanel` 的收合、展開、可存取狀態與內容不可互動。
- 左右工作欄顯示切換。
- 窄螢幕抽屜互斥行為。
- 場景選擇器仍呼叫原本的預設與生成場景回呼，並支援 Escape／外部點擊關閉。
- `SimulationPanel` 既有測試保持通過，確認八個子面板與請求流程未受影響。
- 既有 GPS、裝置、遙測、影像與場景測試保持通過。

完成前執行：

```powershell
Set-Location frontend
npm test
npm run build
```

若內嵌瀏覽器可用，再以桌面寬螢幕與約 1000px 窄螢幕檢查：無遮擋、欄內捲動、面板縮放、抽屜互斥、場景選單與鍵盤焦點。若瀏覽器仍不可用，必須明確記錄缺少視覺驗證，不以建置或單元測試代替。

## 完成條件

- 頂部場景選擇器、七個核心面板與照片紀錄有一致的視覺與外框互動。
- 桌面預設為左右雙側工作區，面板不再以各自硬編碼座標互相覆蓋。
- 核心面板可收合且可垂直縮放；左右欄可隱藏。
- 窄螢幕使用互斥抽屜，手機端既有流程不變。
- 無線模擬面板內部八個子面板與所有後端工作流未變更。
- 前端完整測試與 production build 通過。
